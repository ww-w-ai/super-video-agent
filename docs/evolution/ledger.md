# Self-evolution ledger

What real film work taught the skill, and what was done about it.

## Procedure

No earlier ledger or evolution rule existed in this repo. The ai-native-cowork method
(`shared/references/cowork-method.md`, "retrospective") asks that a retrospective centre on self-evolution,
keep its outputs inside the repository, and promote a candidate only after repeated evidence. This ledger
applies that with the owner's rules (2026-10-16): "4가지 관점으로 평가, 보수적으로, 채택 안된건 남겨두고
다음에 또 나타나면 카운팅".

- **Lenses**, each scored 0–3: **Q** outcome quality (did it hurt a delivered video), **E** efficiency
  (time, GPU, paid API, tokens), **S** safety and rule compliance (did or could an agent break an owner
  rule or spend without asking), **G** generality (does it apply beyond the one project).
- **Adopt** only when the evidence is concrete (a file:line or a measured incident), the change is small and
  local (a sentence, a default, a check), G is 2 or more, and it cannot break existing users. Project
  preferences stay in the project. Anything uncertain stays **pending**.
- **Count** = the number of separate evolution checks in which the item appeared (one check counts once,
  however many films in it showed the item; those films are listed as evidence). An item seen again in a
  later check gets count + 1 and a new "last seen"; no new row. A pending item with count ≥ 3 is promoted:
  the next check designs and adopts a fix unless it is shown unsafe.
- **Rejected** = not the skill's to change (environment, a project's own tool, not reproduced). Rejected rows
  stay so a recurrence is recognised.
